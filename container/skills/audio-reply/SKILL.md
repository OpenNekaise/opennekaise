# Audio Reply

Pure text-to-speech: you compose the reply text, OpenAI's TTS endpoint speaks it back as audio. Nothing about the wording is generated by OpenAI — what you write is exactly what the user hears.

## When to use

Trigger ONLY on explicit user requests for audio. Default to text otherwise.

Examples that should trigger:
- "reply with audio"
- "say it out loud"
- "send a voice message"
- "respond with audio"
- "answer in audio"

If the user did not ask for audio, reply with text as usual.

## How to use

1. Compose the exact text you want spoken — keep it short, conversational, and free of markdown / URLs / code blocks (those don't speak well).
2. Pipe the text to the helper:

   ```bash
   echo "Room 101 is currently 22 degrees Celsius." \
     | python3 "${CLAUDE_SKILL_DIR}/say.py" --voice alloy
   ```

   The script prints the absolute container path of the generated audio file, e.g.
   `/workspace/group/audio/20260508-153012-room-101-is-currently.mp3`.

3. In your reply to the user, attach the file by wrapping that path in `<file>` tags. The host uploads it to the channel automatically:

   ```
   Sure — here you go.
   <file>/workspace/group/audio/20260508-153012-room-101-is-currently.mp3</file>
   ```

   Plain text alongside the tag is fine; both the text message and the audio are sent.

## Options

| Flag | Default | Notes |
|------|---------|-------|
| `--text "..."` | stdin | Alternative to piping via stdin. |
| `--voice` | `alloy` | One of: alloy, ash, ballad, coral, echo, fable, nova, onyx, sage, shimmer, verse. |
| `--format` | `mp3` | One of: mp3, opus, aac, flac, wav, pcm. mp3 plays inline in Slack. |
| `--model` | `gpt-4o-mini-tts` | Cheapest option. Alternatives: `tts-1`, `tts-1-hd`. |
| `--name slug` | derived from text | Override the filename slug. |

## Notes

- TTS is billed per character of input. Keep the text short — you wouldn't want to read a wall of text aloud anyway.
- Strip markdown, code blocks, URLs, and long IDs before sending. They sound terrible and waste characters.
- If `OPENAI_API_KEY` is missing, the script exits with code 2 and a clear error. Fix by adding `OPENAI_API_KEY=sk-...` to the host `.env` and restarting `opennekaise`.
- Output lives under `/workspace/group/audio/` (mounted to the group folder on the host). Old files accumulate there — clean up periodically if disk space matters.
